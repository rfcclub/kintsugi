# Design: Phase 6 — Sessions and Threads

## Storage Layout

```text
~/.kintsugi/
  sessions/
    index.jsonl                          # session metadata index
    2026/
      05/
        20/
          <session-id>.jsonl             # session event log
          <session-id>.jsonl
        21/
          <session-id>.jsonl
```

### Session ID

Format: `kng-<timestamp>-<random>`

Example: `kng-20260520t143052-a3f7`

- `kng` prefix distinguishes kintsugi sessions.
- Timestamp: `YYYYMMDDtHHMMSS` in local time.
- Random: 4 hex chars for uniqueness.

Generated by `nanoid` or a simple `crypto.randomBytes(2).toString("hex")`.

### Directory Creation

On first event write, create the date directory if it doesn't exist:

```ts
const dir = path.join(homedir(), ".kintsugi", "sessions", year, month, day);
mkdirSync(dir, { recursive: true });
```

## Event Store

### Session File Format (JSONL)

Each line is a JSON object. Two line types:

```jsonl
{"type":"session.start","id":"kng-20260520t143052-a3f7","startedAt":"2026-05-20T14:30:52Z","echo":"~/.config/kintsugi/substrate","provider":"mock","model":"mock"}
{"type":"message","role":"user","text":"hello","at":"2026-05-20T14:30:55Z"}
{"type":"event","event":{"type":"assistant.delta","text":"Mock"}}
{"type":"event","event":{"type":"assistant.delta","text":" response"}}
{"type":"event","event":{"type":"assistant.completed","text":"Mock response received."}}
{"type":"message","role":"assistant","text":"Mock response received.","at":"2026-05-20T14:30:55Z"}
{"type":"tool.call","toolName":"read_file","args":{"path":"src/cli/args.ts"},"decision":"allow","at":"2026-05-20T14:31:00Z"}
{"type":"tool.result","toolCallId":"tc-1","output":"export type CommandName...","isError":false,"at":"2026-05-20T14:31:00Z"}
{"type":"session.end","endedAt":"2026-05-20T14:32:00Z","reason":"user_exit"}
```

Line types:

| `type` | Purpose | Fields |
|--------|---------|--------|
| `session.start` | Session metadata | id, startedAt, echo, provider, model |
| `message` | Conversation message | role, text, at |
| `event` | Runtime event (for replay) | event (RuntimeEvent) |
| `tool.call` | Tool invocation record | toolName, args, decision, at |
| `tool.result` | Tool output record | toolCallId, output, isError, at |
| `session.end` | Session close | endedAt, reason |

### Write Pattern

Events are appended (not rewritten). Each `runTurn()` iteration appends lines to the session file. The file is opened in append mode and flushed after each line to survive crashes.

```ts
class SessionWriter {
  private fd: number;

  constructor(sessionPath: string) {
    this.fd = openSync(sessionPath, "a"); // append mode
  }

  writeLine(obj: unknown): void {
    const line = JSON.stringify(obj) + "\n";
    writeSync(this.fd, line);
    // flush is implicit for small writes; can fdatasync for safety
  }

  close(): void {
    closeSync(this.fd);
  }
}
```

## Session Index

`index.jsonl` — one line per session, appended on `session.start`:

```jsonl
{"id":"kng-20260520t143052-a3f7","startedAt":"2026-05-20T14:30:52Z","endedAt":"2026-05-20T14:32:00Z","messageCount":3,"provider":"mock"}
{"id":"kng-20260520t150000-b2e1","startedAt":"2026-05-20T15:00:00Z","endedAt":null,"messageCount":0,"provider":"openai","model":"gpt-4o"}
```

Index entries are compact: no full message content, just metadata. The index remains append-only: `session.start` appends an entry with `endedAt: null`; `session.end` appends a second entry with `endedAt`, final `messageCount`, and `totalTokens` when provider usage is available. Readers deduplicate by session id and keep the latest entry. The index is never rewritten during normal operation.

## Session Replay

`--resume <id>` replays a session:

1. Read the session JSONL file.
2. Parse each line. Skip malformed lines (log warning).
3. Reconstruct `runtime.prompts` from `message` lines.
4. Reconstruct `runtime.substrate` from `session.start.echo` (re-load Echo).
5. Provider and model are set from `session.start` fields.
6. TUI continues from the restored state.

Replay restores messages and tool call records, but never re-executes tools. After replay, Phase 3's session state layer includes the restored pre-resume conversation.

```ts
function replaySession(sessionPath: string): KintsugiRuntime {
  const lines = readFileSync(sessionPath, "utf-8").split("\n").filter(Boolean);
  let startMeta: SessionStart | undefined;
  const prompts: RuntimeMessage[] = [];

  for (const line of lines) {
    try {
      const obj = JSON.parse(line);
      if (obj.type === "session.start") startMeta = obj;
      if (obj.type === "message") prompts.push({ role: obj.role, text: obj.text, at: obj.at });
    } catch {
      // Skip malformed line
    }
  }

  const runtime = bootRuntime({
    substrate: startMeta?.echo,
    noSubstrate: !startMeta?.echo,
  });

  runtime.prompts = prompts;
  return runtime;
}
```

## Threads Command

`kintsugi threads` reads the index and renders:

```text
Recent sessions:
  kng-20260520t143052-a3f7  2026-05-20 14:30  3 messages  mock
  kng-20260520t150000-b2e1  2026-05-20 15:00  0 messages  openai/gpt-4o
```

## Graceful Corruption Handling

- Malformed JSON lines: skip, increment warning counter, continue.
- Missing session file: show "session not found" error.
- Partial writes (crash mid-line): the line is incomplete JSON → skipped on replay.
- Missing `session.start`: replay what we can from messages, log warning.
